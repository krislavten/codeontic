CI 面收编过程中连带的几处跨命令变更与既有缺陷修复。单独列出来，因为它们不属于任何一条新命令，但会改变现有接入方看到的行为。

**空值 flag 一律拒绝**（影响所有命令）

`--repo-root ""` 过去经 `path.resolve("")` 变成**当前工作目录**，于是「调用方到底传没传」这个判断在下游永远得到「传了」，而扫的是另一棵树；`--base ""` 是 falsy，会让基线比对静默关闭，基线上早已存在的 error 全被判成本次引入。两者都是 CI 原生形态——`--base "${{ env.BASE }}"` 变量没设就长这样，且看起来是一个正常的 argv。

现在在 flag 解析层统一拒绝并说明「可能是未设的 CI 变量」。**接入方如果此前存在空变量，会从「静默跑错」变成「明确报错」**——这是有意的方向。

**`gate` 的 `--repo-root` 改为必填**

不给它，anchor-existence 与 INV-1 整层不跑，而剩下的模型级检查照样报「没有 error」——一次只查了一半的运行，读起来和全绿一模一样。要模型级检查单独跑，用新的 `--model-only`，裁决里会写明哪几层没跑。

**`Violation` 新增可选的 `identity`**

用于「跨两棵树判断是不是同一条发现」。存在理由：有些 message 带位置（`file.ts:42`），而位置会因为与该发现无关的编辑而移动——在一条陈年 INV-1 违规上方加一行 import，不该让它读起来像新引入的。哪部分是发现、哪部分只是它今天所在的位置，只有产出它的 check 知道。`CheckResult` 同步新增 `debtIds`（债务增减是两棵树之间的属性，比较方需要原始集合）。

**修复：`check --diff` 在子目录 `--repo-root` 下几乎什么都没做**

`git diff --name-only` 无论在哪个目录执行都输出 git 顶层相对路径，而 INV-1 的候选文件与模型锚点都是 repoRoot 相对。`--repo-root` 等于检出根时两者重合（所以一直没被发现）；指向子目录时交集恒空——INV-1 扫 0 个文件并报告干净，`affected` 也映射不到任何节点。

**修复：`baseline-growth` 在符号链接路径下静默跳过**

它用 `relative(gitRoot, modelDir)` 拼 pathspec，两侧都没先 realpath。macOS 的 `$TMPDIR`、以及 `/var` 下的 CI checkout 都会走符号链接，算出来的 `../../..` 形状 pathspec 匹配不到任何文件，于是整个 baseline 检查被跳过——而「基线上没有债务记录」本身是合法状态，所以没有任何一句话提示它没跑。
